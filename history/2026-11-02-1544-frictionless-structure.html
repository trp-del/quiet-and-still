Quiet & Still · proposals · 2 Nov 2026, 15:44 · revised 16:57 · built 17:51

Write first. Let the structure settle around the writing.

So far the plugin has been about how Logseq looks. Friction is the other half of quiet: every time you stop writing to open a property panel, visit a second page, or scroll a pile of linked references, the outline gets louder than the thought. These ten proposals move structure out of the writing path. You type, and the properties, relations and views form around the text at quiet volume.

Revised after your notes. Each demo now plays in time: press Play, or let it start when it scrolls into view, and the caption says what is happening at each step. Your note and the answer sit beside the proposals you questioned.

Built at 17:51, all but 09, and checked in the Illness Test Graph. One rule runs through them: the plugin suggests on one quiet line under the block, and writes nothing until you press the accept key. That key is Hyper (⌃⌥⇧⌘ together, released with no other key), because Tab indents in Logseq. ⌃⇧↩ is the alternative in settings.

Linking

How nodes point at each other, and how you read those links later.

01

Paired relations

A node property is a relation, and every relation has two ends. Declare a pair once (Treated by ↔ Treats), and setting one end fills the other. Write Treated by: Dr. Mei Chen on Fatigue, and Dr. Mei Chen's page gets Treats: Fatigue in its own properties, without you going there.

You asked: how will it be confirmed this occurs? Three ways, from the moment you write to months later.
At once
When you commit the value, a line under the property says ⇄ Added to Dr. Mei Chen as Treats, with Undo. It flashes amber, then settles to quiet.
On the other page
The mirrored value carries a ⇄ mark. Pointing at it says which page and property set it.
Over time
A command, "Check pairs", finds every pair where one end is missing (say, edited while the plugin was off) and lists them with a Fix button. The plugin's tests check write, remove and undo both ways.
Built as
Pairs named in settings: Treated by <-> Treats; Related. On each change (and a five-second tick, since Logseq sends no event for page properties) the plugin reads every value of the paired properties and writes or removes the other end with upsertBlockProperty, so queries and tables see both. The confirmation lasts ten seconds; Hyper undoes both ends.
Effort
Medium
02

Relations, not a reference pile

Linked references are grouped by how the other node points here: first by the property that holds the link, then by tag, and only then the loose mentions in prose. Each group is a line of node names you can open, not a stack of breadcrumbed blocks.

Why it helps. A flat list of fourteen blocks answers "where does this name appear?" The question you usually have is "what is this connected to, and how?" The property already says how. The list throws that away.

Order
Paired properties (from 01) · other node properties · tags · journal mentions, folded, with a count.
Built as
A section above Logseq's linked references. Pages show as links; blocks fold under their tag (#Consultation · 28) and open to a list, each opening in the sidebar. On Dr. Mei Chen it shows Decided by, Topic and Provider.

03

One name, one node

When the name you're typing is close to a node that exists (a missing period, a different case, a known alias), the existing node comes first in the popup, and a new one is offered second, with the reason shown. If you create it anyway, a whisper under the block asks once whether to make it an alias.

Why it helps. Duplicates are friction you pay later: split references, half the properties on each copy, and a merge you have to remember to do. Catching it at the keystroke costs nothing.

Matches
Punctuation and case, initials (M. Chen), aliases, and edit distance of one or two letters.
Built as
Logseq's autocomplete can't be reordered by a plugin, so the near match shows on the quiet line under the block. Hyper replaces [[Dr Mei chen with [[Dr. Mei Chen, and Logseq's own popup then finds it.

Writing

Adding structure without taking your hands or eyes off the sentence.

04

Shorthand that stays

Type properties inline, the way you'd say them, with no colon: due Friday, provider Dr. Mei Chen, severity 3. A quiet line under the block shows what it read. Hyper sets the properties. The words stay in the sentence exactly as you wrote them.

You asked: can the colon go? It looks odd Yes. Without a colon, prose like "due to the iron" could be misread, so two things keep it safe: a phrase only counts when its value fits the property (a date, a page that exists, a number), and nothing is written until you press Hyper.
You said: stripping the shorthand takes away the content Right. The first version moved the words out of the sentence. Now nothing is removed. The text is the source and the property follows it: change "Friday" to "Monday" in the sentence and the Due date changes with it.
Rules
Only property names you've defined, and aliases you set (for = Project). Dates: Friday, next Monday, tomorrow, in 2 weeks, Nov 6, 2026-11-06. Nothing inside [[links]].
If they part
Change "Friday" to "Monday" and the line offers the new date; Hyper updates it. Delete the words and the property stays. The sentence is never rewritten for you.
Built as
Reads the editor as you type and resolves phrases against your properties and pages. Checked in the test graph: Provider, Date (Nov 6) and Severity set from one sentence, text untouched. The dotted mark on the words isn't built; the quiet line does that job.

05

The last block's shape

When you press Enter after a block that has a tag and properties, the new block shows that shape as a ghost: the tag and the property names, no values. Hyper on the empty block takes the shape; typing anything else ignores it.

You asked: doesn't Tab indent the bullet? It does: Logseq binds Tab to indent, so Tab can't accept anything. Every suggestion now uses one accept key, Hyper, and Tab keeps indenting.

Why it helps. Logs repeat: symptoms, doses, readings, meetings. Re-entering the tag and the same property names on every line is the most common reason structured logging gets abandoned.

Takes
Tags and property names from the previous sibling. Values copy only for properties marked "repeat" (a medication's dose, a project).
Built as
The quiet line under the empty block names the shape; Hyper adds the tags and copies the values you list under "Values to repeat". Checked: #Consultation and Provider carried to the new block.

06

Create without leaving

You link a name that doesn't exist yet and give it a tag. The new page is made with that tag's fields already on it, and one quiet line opens under the block you're writing, so you can fill the fields right there. What you type lands on the new page as you type it.

You said: I don't understand, show it in real time Play the demo. The left pane is your journal; the right pane is the page being created. You never leave the left one.
Keys
Hyper accepts the offer. Enter saves a field and moves to the next. Esc closes the line, leaves the rest for the sweep (08), and puts you back in the block.
Built as
When a block with a tag links a page created in the last few seconds, the quiet line offers to give the page that tag. Values land on the new page when you press Enter. A value that doesn't fit is refused with a reason ("No page named …").
Effort

Shaping

Where structure lives on the page, and when you deal with it.

07

Ambient properties

Set a property once on a parent block and mark it ambient. Every block under it then counts as having that value too: in queries, in tables, in the relation groups from 02. You write Project: Fatigue on the appointment, and the notes under it are Fatigue notes without you typing it on each.

You said: I can't see the far-right text It was set at whisper and pushed to the far edge, so it was too faint to read. Now the inherited value sits right after each note's text at quiet, as ↳ Fatigue, and the thread line under the parent darkens to show the range it covers.
Rules
A note's own value wins over the inherited one. Moving a note out from under the parent drops what it inherited. Page properties can be ambient for the whole page.
Built as
Name the properties in settings ("Ambient properties: Project"). Worked out from the outline, never copied, so moving blocks leaves nothing stale. Checked: "Ferritin came back at 14 ↳ Dr. Mei Chen" on the same line, at quiet, and the table (10) shows it in empty cells.
Effort
Medium Logseq's built-in queries won't see it; the plugin's views (02, 08, 10) will.

08

Fill later, in one sweep

A tag never stops you to ask for its properties. Missing values collect as a quiet count at the top of the page. When you choose, open the sweep: every block on the page with empty fields, as one table, where Enter fills a cell and moves down the column.

You said: show it in time Play the demo: three doses logged without a single interruption, the count rising, then one sweep that fills all three.
Counts
Only properties the tag marks as wanted. Optional ones never show up as missing.
Built as
A quiet count at the bottom right ("5 fields to fill · sweep") and the command "Sweep this page". Click either for the table; Enter saves and moves down the column. Every property a tag defines counts; there's no "optional" marker yet.

09

Properties in the margin

Block properties move out of the text column into a quiet right margin, beside the block they belong to. The prose reads as continuous paragraphs, and the bullets keep their normal spacing whatever the properties are.

You asked: how will it handle many? Large gaps between bullets The margin has its own flow, so properties never add space between bullets. An unfocused block shows its first property and a count (+5). The focused block shows all of them, running down the margin past its neighbours; their notes step down and fade to whisper, then return when you move on. Past eight properties the note ends with "open as table" (10).
Falls back
Below about 900 px the margin folds back under the block, collapsed to the first property and a count.
Ships as
The block's properties area is taken out of the text flow and placed in the margin by a small layout pass that stacks notes without overlap. It's a fixed layout, not a hover effect, so RULES.md's paint-only hover rule still holds.

10

Prose and table, one key apart

Any block's children can flip between the outline you write in and a table of the same blocks, with their properties as columns. One shortcut flips back. You write in prose, then turn it into a table to compare, sort or fill, without building a query.

Why it helps. Structure is easiest to edit in a grid and easiest to write in sentences. Today you pick one per page, or build a query view that lives somewhere else. These are the same blocks, so they should be one keystroke apart.

Columns
The union of the children's properties, ambient ones (07) included, in the order the tag defines.
Built as
⌘⇧T opens a table of the block's children over the block, with their properties, tag fields and inherited values as columns; Esc or ⌘⇧T flips back. Logseq's own table view isn't reachable from a plugin for a block's children, so it's a panel rather than a view.

What this changes about the plugin

Read before choosing what to build.

It starts writing to the graph

Everything so far only restyles. Proposals 01, 04, 05, 06 and 08 write properties. Each needs undo that works in one step, and its own setting, off until it's trusted.

Start where it's read-only

02 and 03, both agreed, never change data and remove the most daily friction. 01 then makes 02 richer, since each pair shows up as its own group.

The rules still hold

Everything new appears at quiet or whisper, nothing opens a modal, and the only amber is a value that just changed. 09 is the one that touches layout, so it's a fixed choice, never a hover effect.
